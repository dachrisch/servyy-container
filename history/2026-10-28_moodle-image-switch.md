# Moodle switches from a self-built image to `erseco/alpine-moodle`

**Date:** 2026-10-27 (evening) / 2026-10-28
**Commit:** `f6edd97` (switch), plus the `MOODLE_SITENAME` fix that followed
**Supersedes:** the image decision in
[2026-10-27_moodle-offd-blank-instance.md](2026-10-27_moodle-offd-blank-instance.md)

## Why

The first build used `moodlehq/moodle-php-apache:8.3` + the Moodle 4.5.12 tarball, because Moodle HQ
ships no image that contains Moodle — so "official image, pinned to the migration version"
mechanically means building one. That worked, but it left us owning the PHP patch cadence: a locally
built image has no upstream rebuild, nothing for watchtower to pull, and no registry. Asked "are we
exposed to the latest PHP bug", the honest answer was "not today, by accident of build timing".

## What changed

| | before | after |
|---|---|---|
| image | built in-repo from `moodlehq/moodle-php-apache:8.3` + 4.5.12 tarball | `erseco/alpine-moodle:v4.5.15` |
| web server | Apache + mod_php | nginx + php-fpm (port **8080**, unprivileged) |
| cron | separate `moodle.cron` container | inside the image (runit) |
| `config.php` | Ansible template, bind-mounted | generated by the image from env |
| install / upgrade | manual `admin/cli/install_database.php`; upgrade guard entrypoint | image runs `install.php` / `upgrade.php` itself |
| url | `https://host/offd/moodle` | `https://host` (root) |
| dataroot owner | uid 33 (www-data) | uid **65534** (`nobody`, Alpine) |
| patch cadence | manual deploy + rebuild | renovate PR on the tag, then deploy |

Deleted: `moodle/app/` (Dockerfile + entrypoint), `templates/moodle.config.php.j2`, the
`world_readable_paths` entry, the `compose_build` opt-in usage, the `moodle.cron` service.

## The version choice, decided by data

`v4.5.12` exists and would have matched live offd.de exactly — and was rejected: that tag was built
2026-07-29 and contains **PHP 8.3.15 (Dec 2024)**, i.e. exposed to a long list of PHP CVEs including
the two 2026-10-21 criticals (`CVE-2026-109618` OOM-corruption RCE, `CVE-2026-109619` stale-state RCE).
`v4.5.15` was built 2026-10-24 on **PHP 8.3.36**, the patched release. So the import becomes a
patch-level 4.5.12 → 4.5.15 upgrade that the image performs itself, rather than running an unpatched
PHP to preserve an exact version string.

## The price: the URL loses its subpath

The image owns its docroot and upstream Moodle does not support being served from a subpath
(erseco docs, issue #127). wwwroot therefore moves from `https://offd.de/offd/moodle` to
`https://offd.de` — decided deliberately *while the instance is empty*, because after the import it
would mean a search-replace over a live 14 GB database either way.

Still owed, and deliberately **not** done yet (prod LeagueSphere must keep pointing at the old live
site until the replace is proven):

1. `leaguesphere` repo: `MOODLE_URL` in `secret_main.yaml` and `secret_stage.yaml`.
2. `leaguesphere` code: the hardcoded `"/moodle/…"` segments in `officials/service/moodle/moodle_api.py`
   and `moodle_service.py`, plus their tests.
3. A one-time `wwwroot` replace for teacher-entered absolute links inside course content.

## Verified (both hosts, fresh installs)

```
moodle.moodle   erseco/alpine-moodle:v4.5.15   healthy   PHP 8.3.36
moodle.db       mariadb (pinned digest)        healthy
https://m.leaguesphere.app/               200  Startseite | moodle
https://m.leaguesphere.app/login/index.php 200  Anmeldeseite | moodle (form present)
https://leaguesphere.app/                 200  LeagueSphere  (alias `app` unaffected)
```

Install log on servy: `Installation von Moodle 4.5.15 (Build: 20261005)` … `xmldb_main_install`,
~500 tables, runit then starts nginx + fpm + cron. Install took ~260 s, which is why the healthcheck
`start_period` is 120 s and nginx only appears after it.

## Two traps worth keeping

- **`MOODLE_SITENAME` must not contain spaces.** The image builds `install.php` args with
  `--fullname=$MOODLE_SITENAME` unquoted; "Flag Academy" becomes two argv entries and first boot dies
  with `Nicht erkannte Optionen: Academy`. The real display name arrives with the imported DB.
- **The dataroot uid is an Alpine one (65534).** Copying the previous owner (33) is silent and breaks
  later.

## Rollback

Revert `f6edd97`: restore `moodle/app/`, the config template and the cron service, point
`moodle_data_root` at the same directory and re-own `moodledata` back to 33. The database is
compatible in the older direction only up to a point (4.5.15 → 4.5.12 downgrade is not supported), so
in practice rollback means wiping the blank instance — which is why this was done before the import.
