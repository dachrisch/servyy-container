# Git over SSH for ci.lehel.xyz (host sshd passthrough on port 22)

**Date:** 2026-11-23
**Status:** ✅ Live on `servy.lehel.xyz` (deployed 2026-11-23); client key provisioned via setup-home
**Relates to:** `2026-11-20_forgejo-platform-setup.md` (listed Git-over-SSH as a follow-up), `2026-11-23_ci-server.md`

## Problem

Forgejo was HTTPS-only (`DISABLE_SSH=true`, no published port). The goal was
`git@ci.lehel.xyz:cda/<repo>.git` on the **standard port 22**, with no
alternative port. `ci.lehel.xyz` rides the `*.lehel.xyz` wildcard to servy, and
servy's own sshd already holds 22.

## Options considered

| Option | Verdict |
|---|---|
| Publish Forgejo's built-in SSH on 2222 | Rejected: port switch for every client, plus guard, edge-filter and Hetzner changes. |
| Dedicated IP for `ci` + sshd `ListenAddress` pin | Rejected: cost, DNS override, lockout risk. |
| **Host sshd passthrough** | **Chosen.** Port 22 is already open everywhere. No new listener, firewall, DNS or guard change. |

## Solution

```
git@ci.lehel.xyz:22 -> servy sshd, Match User git
  AuthorizedKeysCommand /usr/local/bin/forgejo-keys %u %t %k
      -> sudo /usr/local/sbin/forgejo-exec keys …  -> docker exec ci.forgejo forgejo keys -e git …
  forced command (from Forgejo) /usr/local/bin/forgejo-serv key-N
      -> sudo /usr/local/sbin/forgejo-exec serv key-N -> docker exec -i -e SSH_ORIGINAL_COMMAND ci.forgejo forgejo serv key-N
```

- **Forgejo** (`forgejo.env.j2`): `DISABLE_SSH=false`, `START_SSH_SERVER=false`,
  `SSH_PORT=22`, `SSH_DOMAIN=<service_host>`,
  `SSH_CREATE_AUTHORIZED_KEYS_FILE=false`, and
  `SSH_AUTHORIZED_KEYS_COMMAND_TEMPLATE=/usr/local/bin/forgejo-serv key-{{.Key.ID}}`
  (Jinja `{% raw %}`).
- **Why the template override:** Forgejo's default forced command is
  `{{.AppPath}} --config=… serv key-N`. In the rootless image AppPath is
  `/app/gitea/gitea`, a path that exists only in the container. The override
  avoids creating `/app/gitea` on the host.
- **Host** (`forgejo_bootstrap/tasks/ssh_passthrough.yml`, tags
  `user.docker.ci`, `user.docker.ci.ssh`):
  - system user `git`, password `*` (no password, but not locked).
  - `forgejo-exec`, the only root entry point. It validates every argument and
    builds the docker command itself.
  - `forgejo-keys` and `forgejo-serv` shims.
  - `/etc/sudoers.d/forgejo-git`: only the wrapper, plus `env_keep SSH_ORIGINAL_COMMAND`.
  - `/etc/ssh/sshd_config.d/zz-forgejo-git.conf` (Match block: no forwarding,
    TTY or agent).
  - Validation: the fragment with `sshd -t -f`, then the full config with
    `sshd -t`, then `reload`. A bad config never reaches a reload.
- `git` is **not** in the docker group.

## Known limits

- `ci.forgejo` down: `git@` logins fail as "Permission denied (publickey)".
- `MaxAuthTries 3` (host hardening): with many agent keys, use `IdentitiesOnly`.
- Each git operation logs two sudo lines to auth.log (kept for audit).
