# SSH Key Incident & Recovery (2026-08-25)

## Incident
OpenCode GitHub SSH key accidentally committed to git and exposed in commit `23c6cb1`. GitHub detected and revoked the key, interrupting SSH access to GitHub.

**Files affected:** `ansible/plays/vars/.opencode_github_ssh_key`

## Root Cause
SSH private key file was staged and committed to git history instead of being kept in git-ignored secrets or ansible-vault.

## Resolution

### 1. Git History Cleanup
- Used `git filter-branch` to remove the SSH key file from all 1484 commits
- Force-pushed cleaned history to origin/master
- Commit hash changed: `23c6cb1 → 0de6b61`
- GitHub link now 404s (file permanently removed from all commits)

### 2. Vaultwarden Backup Fix
Fixed idempotency issue in `push_items.yml`:
- **Problem:** Task only checked if items exist, not if secret values changed
- **Solution:** Updated task to compare actual secret values and update on changes
- **Commits:**
  - `5d8ab05` - Added value-based idempotency check
  - `e6eb506` - Optimized to map only relevant items (not entire vault)
  - `32d112d` - Fixed Ansible filter syntax (`rejectattr`)

**Result:** Vaultwarden now properly updates SSH key backups when rotated, not just on creation.

### 3. Key Rotation
- Ansible regenerated new SSH key during deployment
- New key automatically pushed to Vaultwarden
- Vaultwarden backup properly detected secret change and updated

**Deployment output:**
```
opencode api key (lehel): unchanged
opencode github ssh key (lehel): updated
```

## Verification
✅ Revoked key removed from git history  
✅ New key generated by Ansible  
✅ New key backed up to Vaultwarden with proper value comparison  
✅ Vaultwarden idempotency improved for future key rotations  

## Prevention
- Keep SSH keys in git-ignored files or ansible-vault
- Vaultwarden serves as off-host backup for critical secrets
- Test key rotation workflow to ensure backups update correctly

## Files Changed
- `ansible/plays/roles/vaultwarden/tasks/push_items.yml` - Added value-based idempotency and update logic
