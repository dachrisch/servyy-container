# graphify — CLI on the opencode server + shipped skill

**Date:** 2026-11-11
**Type:** Server tooling / skill
**Status:** Implemented, deployed to `codey.lehel.xyz`

## Summary

`graphify` (`graphifyy`, "any folder → queryable knowledge graph") is now usable from
sessions on the opencode server: the CLI is installed by `startup.sh` on every boot,
and the skill itself ships from setup-home's `agent-config/skills/graphify/`
(`graphify` added to `opencode_server_shared_skills`).

## Reason

The skill cannot bring its own CLI here, and the CLI cannot bring its own skill:

- `./skills` is bind-mounted **read-only** (`/root/.config/opencode/skills:ro`), so
  `graphify install --platform opencode` inside a session cannot write the skill;
- the image carries no `uv`, so the skill's Step 1 bootstrap (`uv tool install
  graphifyy`, then pip) has nothing to install with;
- nothing is baked into the image — it is upstream `ghcr.io/anomalyco/opencode` — so
  boot-time install is the only place under our control.

## Detailed Changes

| File | Change |
|---|---|
| `ansible/plays/roles/opencode/defaults/main.yml` | `graphify` added to `opencode_server_shared_skills` (copied from setup-home `agent-config/skills/graphify/`). |
| `opencode/scripts/startup.sh` | New §3c: `python3 -c 'import graphify'` guard → `python3 -m pip install --no-cache-dir --break-system-packages graphifyy`; warn-and-continue on failure, no-op inside a boot. Then a drift warning when `graphify --version` (floating) disagrees with the shipped skill's `.graphify_version`, and `graphify-out/` seeded into git's global excludes (`/root/.config/git/ignore`). |
| `opencode/SKILLS.md` | `graphify/` entry: generated by the CLI, canonical copy is the OpenCode flavour, refresh procedure, why the CLI lives in `startup.sh`. |
| `opencode/scripts/AGENTS.md` | Note that `graphify-out/` lands in the scanned tree and `/root/dev` checkouts are shared with claude-hub. |

Install size/behaviour: wheel-only (networkx, numpy, rapidfuzz, pyyaml, tree-sitter and
~25 tree-sitter language packs all publish `musllinux_1_2_x86_64` wheels), no compiler,
~40 s added to a container **recreate** only. `graphify` lands on `/usr/bin` (already on
the container PATH).

## Deployment

```bash
cd ansible && ./servyy.sh --limit codey.lehel.xyz --tags user.docker.opencode -e vw_master_password=
```

`ok=61 changed=6 failed=0`; the skill copy and the startup script triggered
"restart opencode container". `-e vw_master_password=` was needed because the controller's
`bw` CLI is logged out — it only skips the idempotent Vaultwarden backup pushes, no secret
changed here. (Note: `--check` cannot validate this play end-to-end; the Vaultwarden
tasks read live `bw` state that check mode never produces.)

## Verification

```bash
docker exec opencode.web sh -lc 'command -v graphify; graphify --version'
# /usr/bin/graphify ; graphify 0.9.106
docker exec opencode.web ls -a /root/.config/opencode/skills/graphify
# .  ..  .graphify_version  SKILL.md  references
docker logs opencode.web | grep -i graphify
# 📍 [Startup] graphify installed
docker ps --filter name=opencode.web    # Up (healthy)
```

Pre-deploy, the wheel closure was proven in the exact prod image in a throwaway container
(`apk add python3 py3-pip; pip install graphifyy; graphify --version` → `graphify 0.9.106`).
