# 2026-10-29 — Traefik 3.6.1 → 3.7.16 (prepared, staged on the test host)

## Summary

`traefik/traefik.yaml` pinned `traefik:3.6.1` while the 3.6 line ended at **3.6.25** and
the current stable line is **3.7.16** (published 2026-10-20). That is ~24 patch releases
of bug and security fixes skipped on the container that fronts every site on both hosts,
plus the whole 3.7 feature line.

This entry is the **upgrade plan, the config changes it requires, and the evidence** that
the new version accepts our configuration unchanged in behaviour. Deploying it is one
`docker compose up -d --force-recreate` per host, run last, deliberately separated from
the other 2026-10-29 memory work.

## Why 3.7.16 and not 4.x

There is no v4 line: the newest release on `traefik/traefik` is `v3.7.16`, and
`v2.11.60` still gets patches for the v2 holdouts. So this is a **minor** jump inside
v3 — no CRD/v2→v3 style migration.

## Migration notes reviewed (v3.6.1 → v3.7.16), and what actually applies to us

Read end to end from `docs/content/migrate/v3.md` on the `v3.7` branch. We run the
**Docker provider + file provider only**, no Kubernetes, so every `k8s/*` and
`ingress-nginx` item is out of scope.

| Version | Change | Applies? | Action |
|---|---|---|---|
| 3.6.7 | encoded-character defaults flipped to *allow* | no change for us (3.6.1 predates the validation entirely, so we already allow) | none; verified byte-identical probe results |
| 3.6.8 | health-check path must be a relative URL | no | we set no `loadbalancer.healthcheck.path` labels (checked all compose files) |
| 3.6.14 | `forwardAuth.trustForwardHeader` deprecated, warns when unset | **yes** | set explicitly to `false` (safe edge default) |
| 3.6.16 | Docker provider needs Docker API ≥ 1.40 | no | both hosts run Engine 29.1.3 (API 1.52) |
| 3.6.19 / 3.7.3 | basicAuth with an empty user list is now an error → router unmounted | watch | we use `usersFile`; the file is rendered by `traefik_dashboard_auth` and is non-empty. A missing/empty file would now produce a **404** instead of a **401** — see the check below |
| 3.7.7 | bare `Host(*)` becomes a real catch-all | no (informational) | we keep `HostRegexp(`.+`)`, which matches identically on 3.6 and 3.7 — a rollback stays free of edge cases. Comment in `dynamic.yaml` updated |
| 3.7.12 | `aliasHeadersStrategy` added; a startup warning per entrypoint that leaves it unset | **yes** | set to `keep` on all entrypoints: silences the warning, preserves today's behaviour exactly |
| 3.7.13 | `Upgrade: h2c` / `HTTP2-Settings` no longer forwarded; rootless request targets → 400 | no | probe confirmed 400 on 3.6.1 too; no h2c backends |
| 3.7.15 | every `CONNECT` → 501 | **yes, harmless** | 3.6.1 answered 405; we do not forward-proxy CONNECT tunnels |
| 3.7.16 | k8s secret refs in middlewares | no | — |

## What changed in the repo

- `docker-compose.yml`: `traefik:3.6.1` → **`traefik:3.7.16`**, with the migration
  summary and the rollback one-liner in a comment. The pending `mem_limit: 384m` from
  the 2026-10-29 memory work lands with the same recreate.
- `traefik.yaml`: `aliasHeadersStrategy: keep` on `web`, `websecure`, `metrics` **and**
  on the built-in `traefik` entrypoint (declared explicitly for that reason only; it is
  not published to the host — the dashboard is reached through the `traefik.lehel.xyz`
  router on `websecure`). Declaring the internal entrypoint is what takes the warning
  count from 4 to 0.
- `dynamic.yaml`: `trustForwardHeader: false` on `opencode-apikey-auth`; the catchall
  comment now records the 3.7.7 `Host(*)` change and why we still use `HostRegexp`.
- `traefik/AGENTS.md`: upgrade procedure + rollback added to the "rules that bite".

## Evidence collected before touching a host

A/B harness on `servyy-test.lxd`: the **real** `traefik.yaml` + `dynamic.yaml`, run under
`3.6.1` and `3.7.16` side by side on loopback ports, docker provider removed from the
static copy so no container was discovered and **no ACME order could be placed**.

| Probe | 3.6.1 | 3.7.16 | Verdict |
|---|---|---|---|
| config accepted, file provider objects built | yes | yes | no dropped middleware/router |
| unknown host over HTTP (catchall + branded page) | 404 + `x-error-page` marker | same | identical |
| unknown host over HTTPS (default cert, no LE order) | 404 | 404 | identical |
| `/%2f…`, `/%5c…`, `/%00`, `%3b`, `%25`, `%3f`, `%23`, `..%2f` | 404 (passed through) | 404 (passed through) | identical — no new 400s |
| rootless target `GET http:example.com/admin` | 400 | 400 | identical |
| `CONNECT example.com:443` | 405 | **501** | documented change, not used by us |
| `Upgrade: h2c` request | 404 | 404 | identical |

Then the **proposed** config (with the two new knobs) was rehearsed on `3.7.16`:
`aliasHeadersStrategy` warnings **0**, `trustForwardHeader` warnings **0**, Prometheus
metrics still served on the `metrics` entrypoint, branded catchall page and TLS catchall
unchanged. Two log lines remain on purpose: the one-shot encoded-characters advisory
(we keep the permissive default) and the known-harmless
`middleware "error-pages@file" does not exist` for `acme-http@internal` at startup.

| `servy.lehel.xyz` | 3.6.1 | 60 (`md5 d5648368…`) | API: 100 routers / 99 enabled / 1 disabled, 38 services, 16 middlewares |

## Pre-existing drift noticed while taking the baseline

On `codey.lehel.xyz` the traefik dashboard router rule is `Host(`traefik.lehel.xyz`)` —
the *servy* hostname — while its local-qualified router is `traefik.codey.lehel.xyz`.
So `traefik.code.lehel.xyz` does not resolve to a router on codey, and codey's dashboard
answering on `traefik.lehel.xyz` is shadowed by servy's DNS. Cause is almost certainly a
stale `SERVICE_HOST` in codey's rendered `traefik/.env` from an older checkout. It does
not affect routing of real sites (each service carries its own `Host()` rule), and it is
**not** fixed here — mixing it into a version bump would make a rollback ambiguous. Worth
its own change: re-render codey's `.env` and recreate.

Two log lines seen for the first time, both triaged:

* `WRN maxResponseBodySize is not configured … middlewareName=opencode-apikey-auth@file`
  — **new in 3.7** (0 occurrences on prod's 3.6.1 logs). Deliberately **not** fixed in
  this change: the option was introduced in 3.6.9 and our fallback image is 3.6.1, so
  adding it would make the documented tag-only rollback break the middleware. It becomes
  follow-up 6, to land once 3.7.16 is accepted. Risk while unset is bounded: the
  forwardAuth target is our own authgate, not an attacker-controlled server.
* `WRN Could not find network named "proxy" for container "/moodle.db"` and its peers —
  **pre-existing**: prod's 3.6.1 log already carries 1 110 of them (db containers that
  keep `traefik.*` labels but are only attached to `internal` networks). Not an upgrade
  artefact; noise to clean up separately.

## Deploy procedure (run when the user is available; ~2 min of blip)

```bash
# 0. backup the ACME store on each host (re-issuable, but LE rate limits are real)
ssh <host> "docker run --rm -v traefik_traefik-certificates:/c -v /tmp:/b alpine \
  cp /c/acme.json /b/acme-$(date +%F).json && ls -l /tmp/acme-*.json"

# 1. new checkout on the host, then force-recreate (config is a single-file bind
#    mount: a plain `up -d` keeps the old inode and never reloads)
ssh <host> "cd ~/servyy-container && git pull -q --ff-only"
ssh <host> "cd ~/servyy-container/traefik && docker compose up -d --force-recreate"

# 2. verify
ssh <host> "docker inspect traefik.traefik --format '{{.Config.Image}} {{.State.Status}}'"
ssh <host> "docker exec traefik.traefik traefik version | head -3"
ssh <host> "docker logs --since 5m traefik.traefik 2>&1 | grep -cE 'aliasHeadersStrategy|trustForwardHeader'"
curl -s https://leaguesphere.app/ -o /dev/null -w '%{http_code}\n'
curl -s https://monitor.lehel.xyz/api/health -o /dev/null -w '%{http_code}\n'
curl -sk --resolve nope.invalid:443:127.0.0.1 -H 'Accept: text/html' https://nope.invalid/ | grep -c x-error-page
# router inventory must match the baseline above (60 / 8, same md5)
```

Order: **servyy-test → servy → codey**. Codey last because it fronts fewer public hosts
(`code.lehel.xyz`, `h.code.lehel.xyz`).

### Rollback

```bash
# revert the tag (git revert of the commit), pull on the host, force-recreate
ssh <host> "cd ~/servyy-container/traefik && docker compose up -d --force-recreate"
```

`aliasHeadersStrategy` and `trustForwardHeader` are accepted by 3.6.1 too, so a rollback
can leave the config as-is: **only the image tag needs reverting**. That is why both knobs
were chosen as no-ops rather than as hardening.

### Known follow-ups (not part of this upgrade)

1. `aliasHeadersStrategy: delete` (or `reject`) on `web`/`websecure` — closes the
   underscore/dot header-spoofing class. Needs per-app verification (PHP, WSGI and NGINX
   backends alias `X_Auth_User` to `X-Auth-User`); do it as its own change.
2. `encodedCharacters.allowEncoded*: false` — rejects `%2f`/`%00`/`%3b`/… in paths.
   Traefik recommends it for backends that are not RFC 3986 compliant; also a behaviour
   change, also its own change.
3. `traefik_dashboard_auth` renders `dashboard-auth.htpasswd`; consider asserting
   non-empty in the role, because since 3.6.19 an empty users file unmounts the router
   (404 instead of 401) with only a log line.
4. codey's stale `SERVICE_HOST` (above).
5. There is **no Renovate workflow** in this repo (`renovate.json` exists but nothing
   runs it), which is why a pin one minor version behind went unnoticed for weeks. Either
   restore the runner or add a monthly manual check to the ops routine.
6. `maxResponseBodySize` on `opencode-apikey-auth` (new 3.7 warning, 3.6.9 option).
   Land it *after* 3.7.16 is accepted, because 3.6.1 cannot parse the field and a
   tag-only rollback would then unmount the middleware.
7. The 1 110 `Could not find network named "proxy"` warnings on servy are stale
   `traefik.*` labels on containers that are only on `internal` networks (db sidecars).
   Cleaning them removes real noise from the log that a genuine routing problem would
   otherwise hide in.
